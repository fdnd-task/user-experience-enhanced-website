## Code opschonen
Nu we al een paar sprints met de server werken is het tijd om deze code eens op te schonen en beter leesbaar te maken. Een paar van onderstaande punten zijn waarschijnlijk al langs gekomen tijdens een practicum. Doorloop met je tafel jullie  server code een probeer deze punten te verbteren:

- Een baseURL aanmaken voor het deel van de fetch url naar Directus endpoint dat steeds hetzefde is (DRY)
- Leesbaardere naamgeving
- Een versie van het server.js bestand maken mét en zonder comments (door de vele comments is de code moeilijk te lezen en te debuggen)
- Herbruikbare code in variabelen opslaan (DRY)
- Code volgens vaste structuur schrijven (per scope/function) variabelen, code logic, function declarations
- Een function één ding laten doen (Single Responsibility Principle)

Advanced:
- Een fetch helper function schrijven met error handling (DRY)
- Routes opsplitsen in aparte bestanden om het server bestand lean and mean te houden (en wat meer richting componenten te denken)



## Sprint review voorbereiden en Readme schrijven
Eerst ga je met je team met studenten die dezelfde opdracht hebben de Sprint Review voorbereiden. Ga met elkaar aan tafel zitten. Laat eerst aan elkaar zien wat je hebt gemaakt deze sprint en aan welke vragen of feedback van de opdachtgever je hebt gewerkt. Bedenk daarna hoe jullie dit gaan presenteren, en bedenk een volgorde van onderwerpen.

### Status bespreken met een docent
We gaan groepjes maken en bespreken wat je aan de opdrachtgever gaat laten zien. Door dit te bespreken met een docent kan je nog even wat vragen stellen en kunnen wij je helpen met tips en tricks voor de laatste loodjes. 



## Readme schrijven
Schrijf daarna een nette Readme, waarin je laat zien wat je hebt gedaan. In de Readme laat je het eindresultaat zien en verantwoord je je ontwerpkeuzes...

Tot slot zorg je ervoor dat je en goede reame hebt waarin je presenteert wat je hebt gemaakt en je ontwerpkeuzes en eigen ideeën begrijpelijk uitgelegd.
